## 三键悬浮底色第二轮：真正的根因（19:00）

上一轮判断错了方向。真因在 `frontend/src/v2-theme.css`，不在 App.css：

1. **两层底色**。`v2-theme.css:401` 的 `body[data-ui-version="v2"] .ant-btn-text:hover { background: var(--gn-bg-hover) !important }` 特异性 (0,3,0)，与 App.css 里 `.titlebar-window-controls > .ant-btn.ant-btn-text` 完全**同分**，两条都带 `!important`。`App.tsx:332-333` 先引 App.css 后引 v2-theme.css，同分看顺序，后者赢 → 按钮本体被涂满，叠上 `::before` 就是两层。关闭键表现为「灰方块套红方块」。
2. **高度被压**。`v2-theme.css:319` 的 `body[data-ui-version="v2"] .ant-btn { height: 30px !important }` 通杀内联 `height: 40`，三键实际是 **40×30**，`inset: 5px` 算出来是 30×20 的圆角长条，不是正方块。此前 App.css 注释写「三键为 40x40 方块（高度由内联样式给出）」，与实际不符。
3. **前板填充露白**。还原图标前板 fill 用了 `--gn-bg-titlebar`，比悬浮底色浅，在底色上盖出一个浅色小方块。

修法：

- App.css 基础规则选择器加 `body[data-ui-version="v2"] .gn-v2-titlebar` 前缀 → (0,5,1)，压过泛化规则；并显式锁 `width/min-width/height/min-height: 40px !important` 与 `padding: 0 !important`。**凡是泛化规则用 `!important` 设过的属性，这里也必须带 `!important`，只靠特异性不够。**
- 删除失效的 restore-front hover 填充规则；前板改 `fill: none`。
- `TitleBarWindowControlIcons.tsx` 的还原图标后板由 `<rect>` 改为**不含重叠段的开放 path**，图标从此与底色解耦。前板保留 class 名（测试依赖该字符串）。
- 坑：规则体内注释不能出现 `{` 或 `}`，测试用 `[^}]*` 抓规则体，会被截断。

验证：写脚本 `%TEMP%/wb-titlebar-check.cjs` 重放 `TitleBarPrimaryActions.test.tsx` 的静态断言，37 项全 PASS（vitest 会被沙箱删除保护拦，改用脚本）。`npm run build` + `wails build -s` 通过，产物 CSS 已核对：base 规则含 40×40 与 transparent、`:before` 只有 `top/right/bottom/left:5px`、close 红块在 `:before`、`restore-front{fill:none}`。

`design/titlebar-window-controls-hover.html` 已按真实原因重写（修复前 / 后 + 暗色 + 还原图标 1:1 放大）。
