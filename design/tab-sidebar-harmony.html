标签栏 × 侧栏收展 · 协调性提案

当前的问题：侧栏收起/展开时，标签栏起点瞬间跳变（从侧栏右边界跳到窗口左缘），且起点处缺少结构性锚点， 标题栏（通栏）与标签栏（被侧栏截断）之间没有对齐关系。以下 4 个方案各自给出收展策略—— 每个窗口的 「收起 ⇄ 展开」按钮可交互演示（0.32s 缓动过渡）。

P1 · 图标条收起 + 贯穿结构线 推荐

侧栏收起不是消失，而是收成 48px 图标条（LOGO/搜索图标保留）。侧栏右边界这条结构线 从标题栏底部贯穿到底部、位置永远存在——标签栏起点移动幅度只有 232−48=184px 且带缓动动画， 视觉上「侧栏收进去」而非「标签栏突然搬家」。结构感、可达性、动画舒适度三者兼得，最接近 IDEA / VS Code 的行为。

P3 · 标签栏把手区 功能最顺

在标签栏最左侧放一个常驻 34px 把手区（三横线图标，点击收起/展开侧栏）。 无论侧栏什么状态，标签栏起点都从把手右侧开始——起点永远稳定；侧栏收起后开关仍在原位可达， 形成天然的「展开入口」。IDEA 侧栏条与现代 IDE 都用这种「把手上移进工具行」的手法。

P4 · 骨架同步收缩 过渡最细腻

P1 的进阶版：收起瞬间侧栏内容不是被裁切，而是降级为骨架条（文本行收缩为居中短横块）， 搜索框收成图标方块——所有元素同步做尺寸动画，全程无裁切、无闪跳。实现成本最高（需要给每个元素 定义收起态形态），但动画质感是四个方案里最好的。
