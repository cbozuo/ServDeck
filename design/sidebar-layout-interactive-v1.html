左侧栏收起 / 展开 · 整体布局优化

点左上角 LOGO 切换（真实行为：App.tsx:7908 handleTitlebarSidebarToggle）。 桌面端收起宽度 = 0（App.tsx:1228-1230），侧栏内全部动作搬到标题栏第二行 （v2-theme.css:4533）。问题：收起后主区从窗口左缘 0px 起算，而展开时是 200px 起算， 同一套内边距在两种宽度下密度观感不一致 —— 下面三套方案对比这个差异的收法。

方案
C 展开态
A

栅格紧致化推荐

收起后主区获得更宽的可视宽度，因此网格列宽、卡片内边距、Hero 尺寸按容器宽度自适应收紧， 让 4 列资源卡在同一行内获得更舒适的呼吸感，内容不至于显得"散"。tab 栏与 Hero 保持同一 22px 基线。 收起前后主区内容左边界不变（都是 22px），切换时零横向位移，只有侧栏在滑动。

收起时：主区 4 列资源卡间距与内边距按容器宽度自适应；tab 与 Hero 左边界锁定 22px，切换无位移。
实现要点：需给 .dtl-root 引入容器查询（container-type: inline-size）或按 data-sidebar-collapsed 切换密度变量。
B

tab 栏自带 gutter局部修补

只解决 tab 栏：给 .dtl-tabs 补 padding: 0 22px，与 .dtl-root 的横向 padding 对齐，浮层 / 分离窗口里也不贴边。改动最小、风险最低。 但整体布局的"密度不一致"没有被处理 —— 收起后主区变宽 200px，卡片和间距仍是展开态的取值。

收获：1 行 CSS 解决 tab 贴边，含浮层场景。
局限：整体布局密度未优化；收起后右侧留白观感偏空。
C

收起时首列动作归入主区改动较大

收起后不在标题栏第二行摊开动作，而是在主区左上角内联一行动作（放在工作台页签行右侧）， 这样标题栏恒为单行、不会因收起而"长高"，主区顶部也更紧凑。 代价是收起态与展开态的动作位置不同，用户需要重新建立位置记忆。

收获：标题栏恒单行，收起/展开不再改变标题栏高度。
局限：动作位置在两种状态下不同，违反位置一致性原则。
