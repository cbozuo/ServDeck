# 服务详情页 · 状态与操作规则核查稿

> 配套原型：`design/service-detail-page-v2.html`
> 对应脚本：`JavaServiceDeploy-servy-cli版本.bat`、`rustfs-service.bat`
> 本文是「哪种状态下哪些操作可用」的**唯一口径**，原型按钮、表单只读、提示文案均以本文为准。

---

## 1. 状态维度

操作可用性由三个维度共同决定，缺一不可。

### 1.1 进程状态 `P`

| 值 | 文案 | 来源 |
|---|---|---|
| `running` | 运行中 | SCM 查询到 RUNNING |
| `stopped` | 已停止 | SCM 查询到 STOPPED |
| `pending` | 转场中 | 已提交操作、等待 SCM 返回（启动中 / 停止中 / 重启中 / 安装中 / 卸载中） |
| `unknown` | 未知 | 服务不存在或查询失败（**补充态**，原型暂未覆盖） |

`pending` 是一个**互斥态**：只要处于转场中，除「查看日志」外的所有写操作一律禁用。

### 1.2 托管状态 `M`

| 值 | 文案 | 含义 |
|---|---|---|
| `managed` | servy 托管 | 已注册进 SCM，有完整安装参数（deploy 非空） |
| `adopted` | 纳管 | 仅监控，未托管注册（deploy 为空） |

### 1.3 生效状态 `E`（补充维度）

| 值 | 文案 | 触发 |
|---|---|---|
| `synced` | 已生效 | 注册信息 = 当前进程所加载的配置 |
| `deployDirty` | 待写回 SCM | 部署参数已改，但未「重新注册」 |
| `confDirty` | 待重启生效 | 配置文件已写回磁盘，但进程未重启 |

> `deployDirty` / `confDirty` 不改变操作可用性，只负责**提示与引导**（见 §5）。

## 3. 两条关键约束的理由

### 3.1 运行中不允许「注册」

- **技术**：servy 注册要改写 SCM 的服务二进制路径（binPath）。Windows 在服务运行期间会拒绝该修改，必须先停止。
- **产品**：脚本 `INSTALL` 内部虽然会自动 `stop → uninstall → install → start`，但**自动中断服务**对使用者是隐形的。UI 要求显式先停止，把「服务会中断」这件事摆到台面上。
- **文案**：`请先停止服务再重新注册`。

### 3.2 运行中不允许修改「部署参数」

- **技术**：JVM 参数（`-Xms2g -Xmx2g`）、程序路径、工作目录都是**进程启动时一次性读取**的。进程已在运行，改这些值不会对当前进程产生任何影响。
- **闭环**：改参数 → 必须「重新注册」才写回 SCM → 而重新注册又要求先停止。所以运行中开放编辑只会制造「改了却没生效」的困惑。
- **正确路径**：停止 → 改参数 → 重新注册（自动拉起）。
- **文案**：`服务运行中，启动参数不可修改` + 一句「请先停止服务」+ 一个「停止服务」快捷按钮，形成闭环。

## 4. 信息归属与字段可变性

### 4.1 一条信息只在一处主展示（消除重复）

之前「概览 → 基本信息」「部署参数 → 启动参数」「运行环境 → 程序文件」三处把**同一批纳管数据**各列了一遍，
且与「添加服务」弹窗里录入的内容完全同源。现收敛为：

| 信息 | 唯一归属 | 性质 |
|---|---|---|
| 服务名 / 显示名称 / 程序文件 / **服务描述** / 纳管时间 | **部署参数 → 纳管信息** | 添加服务时录入，**只读**（服务类型由图标与扩展名即可辨识，纳管来源与托管状态卡重复，均已移除） |
| JVM 路径 / JVM 参数 / 应用参数 / 工作目录 / 日志目录 / 启动类型 / 守护 / 轮转 | **部署参数 → 运行参数** | 可编辑，改动需「重新注册」写回 SCM |
| 启动命令（由程序文件 + 运行参数拼出） | **部署参数 → 命令预览块** | 只读，自带复制 |
| 运行状态 / PID / 运行时长 / 启动时刻 | **Hero（状态徽标 + meta）** | 实时；原常驻状态条与 ⓘ 悬浮状态卡均已删除 |
| PID / 已运行时长 / 启动时刻 | **Hero meta** | 纯运行态 |
| CPU / 内存 / 线程 / 句柄 / 磁盘 IO / 网络 IO / 目录占用 / 连续运行 | **概览 → 资源占用** | 实时采样 |
| 日志文件与内容 | **日志** | |

**已删除的重复展示**

| 删除项 | 原因 |
|---|---|
| 概览「基本信息」面板 | 16 个字段全部与状态条或纳管信息重复 |
| 运行环境「程序文件」面板 | 与纳管信息里的程序文件同源 |
| **「运行环境」整个页签** | 逐块核对：`servy` 版本侧栏底部已有、java 版本由 JVM 路径体现；数据目录容量与概览「目录占用」卡重复；环境自检与部署页的托管状态 / 依赖端口重叠；服务端点与凭据脚本安装时已打印 → **整页取消，页签由 5 个减为 4 个** |
| **常驻状态条（8 格）** | 前三格（运行状态 / PID / 时长）Hero 本来就有，后五格（启动类型 / 托管方式 / 守护 / 轮转 / 依赖端口）与部署参数页整片重复 → **取消面板**；后经确认 ⓘ 悬浮状态卡同样冗余，一并删除 |
| **「依赖端口健康」面板** | 预检 / 巡检结果平时无人查看，且安装流程进度条本身含端口预检步骤 → 取消；依赖端口异常仍由 Hero 常驻告警 pill 提示，「依赖端口异常时不阻止启动」的规则不变 |
| Hero 的 4 个标签 | 与状态条逐项重复 |
| Hero meta 中的服务名 | 面包屑已有 |

**页签最终为 4 个**：概览 / 部署参数 / 日志 / 事件。

### 4.2 字段可变性

| 字段 | 可编辑 | 可空 | 说明 |
|---|---|---|---|
| 服务名 / 显示名称 / 程序文件 | ✗ | ✗ | **纳管后不可变**；要变更需移除服务后重新添加 |
| 纳管时间 | ✗ | — | 系统写入 |
| JVM 路径 | ✓ | ✗ | java.exe 完整路径，注册时为 `--path` |
| JVM 参数 / 应用参数 | ✓ | ✗ | 建议 `-Xms/-Xmx` 成对；内存卡上限取自 `-Xmx` |
| 启动参数（非 Java） | ✓ | ✗ | rustfs：`server <volumes> --console-address ...` |
| 工作目录 | ✓ | ✗ | 注册时为 `--startupDir` |
| 日志目录 | ✓ | ✓ | 空则 servy 不接管 stdout / stderr |
| 服务描述 | ✗ | ✓ | **纳管时录入，归入纳管信息只读**；空则不写 `--description` |
| 启动类型 | ✓ | ✗ | 选 `Disabled` 会禁用「启动」（见 §2 附加约束）|
| 崩溃重启 / 日志轮转 | ✓ | — | 开关，对应 servy 守护与 `--enableSizeRotation` |

**只读态表现**：输入框 `readonly` + 灰化（`.input.locked`）、开关与下拉 `disabled`、面板标题追加「· 已锁定」、面板顶部出现橙色锁定提示条（附「停止服务」快捷按钮）。

### 4.3 就地操作（随字段走，不另设入口）

| 字段 | 就地按钮 |
|---|---|
| JVM 路径 | **选择 JDK** —— 弹层列出自动检测到的本机 JDK（版本徽标 / 发行商版本 / 路径 / 「当前使用」标记），也可手动指定 java.exe；选中后同步刷新安装命令里的 `--path` |
| 工作目录 | 打开工作目录 |
| 日志目录 | 打开日志目录 |
| 启动命令（命令预览块） | 复制 |
| 日志页工具栏 | 打开日志目录 / 下载 |

> **锁定态一致性**：服务运行中时，上表的就地按钮（选择 JDK / 打开目录）**一并禁用** —— 锁定的字段整行不可操作，避免「字段只读但按钮能点」的矛盾观感。查看类需求走日志页（其「打开目录」不受限）。

## 5. 提示与引导（不改可用性，只做闭环）

| 场景 | 提示位置 | 内容 |
|---|---|---|
| 运行中打开「部署参数」 | 表单上方锁定条 | 服务运行中，启动参数不可修改 → 附「停止服务」按钮 |
| 改了部署参数未重装 | 部署页顶部 | 参数已修改，需「重新注册」写回 SCM → 附「重新注册」按钮 |
| 配置文件已保存 | 配置页底部 | 需重启服务生效 → 附「稍后重启 / 立即重启」 |
| 依赖端口异常 | Hero 告警 pill（常驻） | 仅告警**不阻止启动**（与脚本 `WARN` 行为一致）；面板删除后这是端口状态的唯一可见提示 |
| 卸载后 | 部署页 | 托管状态回退为纳管，参数保留可再次注册 |

## 6. 与脚本的对应关系

| UI 操作 | 脚本动作 | 脚本内部行为 |
|---|---|---|
| 注册 / 重新注册 | `[1] Install Service` | `stop` → `uninstall confirm` → `install` → `start` |
| 启动 | `[2] Start Service` | `servy-cli start` |
| 停止 | `[3] Stop Service` | `servy-cli stop` |
| 重启 | —（UI 补充） | `stop` → `start`（脚本无此项，因高频操作而补） |
| 卸载 | `[6] Uninstall Service` | `stop` → `uninstall confirm`（Y/N 确认） |
| 版本信息 | `[5] Version Info` | `java -version` + `servy-cli version` |
| 状态查询 | `[4] Service Status` | `servy-cli status`（对应状态条 8 格） |

## 7. 待确认

1. **停止状态下的「卸载」是否也要二次确认？** 当前：是（弹窗 Y/N，对应脚本 `[6]`）。
2. **纳管服务（deploy 为空）点「注册」时，参数从哪来？** 当前：注册后由 ServDeck 按内置模板生成，需在部署页补填。若希望注册时就带一张参数表单，需要额外设计。
3. **`unknown` 态（服务被外部删除）** 的处理：当前原型未覆盖，建议下一步补「服务已不存在」的空态。
4. **纳管信息写错了怎么办？** 当前口径是「不可编辑，需移除服务后重新添加」——但**尚无「移除纳管」入口**（仅托管服务有「卸载」，卸载后服务仍在列表里）。需要补一个「从 ServDeck 移除」的动作，否则错误信息永远改不掉。
5. **非 Java 服务的「程序文件」是否也可变？** 当前与 Java 一致按只读处理。若 rustfs 换版本换路径是常见操作，需要重新考虑（例如允许「更换程序文件」但仍要求先停止）。
